# 三张模拟实机效果图

## 生成前

先询问是否需要。统一收集已确认的循环、题材、受众、美术特点、参考图及画面方向。按平台和交互选比例；Steam PC 可建议16:9，移动项目按需求选横竖屏，不能把16:9作为所有项目的硬条件。

三图内容须能映射到已确认玩法。只有一种主要玩法时，第二张可展示另一典型阶段或状态；养成未明确时，先澄清成长对象。不能为了三张图发明第二种玩法或新增系统。

使用当前 imagegen 技能规定的工具。要求 Image2 时使用可提供的对应能力；工具不支持指定或无法核验模型时如实描述能力，不伪报模型。调用失败按该技能处理，不擅自改用需密钥或额外付费的方式。

## 画面要求

| 图片 | 必须表达 |
|---|---|
| 主要玩法1 | 正在进行第一种主要活动，场景状态、操作对象、核心交互及必要 UI |
| 主要玩法2 | 另一主要玩法或典型状态，展示独立操作与反馈 |
| 养成界面 | 成长对象、当前状态、提升效果、资源需求及操作按钮 |

三张独立图片，以“完整游戏画面／模拟实机截图／正在操作的功能界面”为目标。避免概念画、宣传标语、设备外框、拼贴和装饰性按钮。

角色、比例、造型、轮廓、色彩、图标、品质颜色、字体和面板保持统一。可先生成一张风格锚点，再与用户参考一起约束其余图；每张功能与构图仍对应不同玩法。

## 提示词组织

1. 用途：高完成度模拟实机或功能界面。
2. 已确认的平台、玩法、题材、美术特征。
3. 逐张标明参考图用于风格、角色、场景还是布局。
4. 本图状态：玩家正在做什么，物件和系统怎样联系。
5. 镜头与比例，保持游玩可读性。
6. 必要 UI：目标、资源、技能、建设、背包或养成，按内容选择。
7. 一致性与排除项：避免海报、概念插画和信息噪声。

为构图补充的外观、名称、配方与数值是展示提案，不自动成为设计定案。

## 检查与交付

查看每张实际结果：是否对应玩法、UI有功能含义、文字图标清楚、三图一致。检查示意逻辑：背包容量与格子数、资源拥有与需求、按钮状态、装备与技能关系、物流连接等。

关键问题针对性修正，避免无边界重画。保存全部最终独立图片到当前项目输出目录，保留文档可用路径。

展示后提供“通过进入立项汇总”“修改／自行补充”“💡 帮我脑暴”。沟通中说明是生成的模拟实机图，不是已运行游戏；最终文档不增加零碎生成备注。

跳过生图时尊重决定；美术展示模块可保留视觉方向或用户允许使用的参考，不伪造图片已生成。
