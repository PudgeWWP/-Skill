# 对话引导

按当前信息调整选项，示例不是固定题库。用户已经提供答案时直接承接。

## 类型入口

“你想做一个什么类型的游戏？可以选一个主要方向，也可以组合多个类型，或直接描述想法和参考游戏。”

| 类型方向 | 典型玩法标注 |
|---|---|
| 卡牌／卡组构筑 | 收集、组牌、效果搭配、策略对战 |
| 策略／SLG | 资源调配、建设发展、排兵布阵 |
| RPG | 角色成长、装备技能、剧情任务、探索战斗 |
| 模拟经营 | 种植生产、店铺或城市经营、收益与扩张 |
| 肉鸽／Roguelike／Roguelite | 随机事件或关卡、构筑、反复挑战 |
| 动作／格斗／平台跳跃 | 攻击闪避、连招、跳跃闯关 |
| 射击 | 瞄准、武器、走位、单人或团队作战 |
| 生存／沙盒建造 | 探索采集、制作工具、建设、环境挑战 |
| 解谜／叙事冒险 | 线索、机关、对话选择、故事推进 |
| 休闲／放置／合成 | 轻量操作、消除合成、自动积累 |
| 体育／竞速／音游 | 运动、驾驶、节奏判定、技巧挑战 |

展示时补上“其他／自行描述”和“💡 帮我脑暴”。不把卡牌自动理解为付费抽卡，也不从“肉鸽”推定死亡惩罚。

## 玩法提问

先问大过程：“玩家进入游戏后先做什么，获得什么，接下来为什么继续？”

只追问当前影响整体体验的缺口：

- 操作：哪些手动，哪些自动，主要决策是什么？
- 循环：行动获得什么，如何投入下一轮？
- 混合：A 如何进入 B，结果如何传递，何时返回或继续？
- 节奏：前中后期活动是否变化，新内容怎样引入？
- 参考：每款产品整体参考还是局部借鉴，哪些保留、哪些改变？

混合玩法可用下表收敛：

| 玩法 | 核心操作 | 输入与输出 | 进入／退出方式 | 与其他玩法的联系 |
|---|---|---|---|---|

脑暴方案要有体验差异，而非同一方案换词。可推荐并说明取舍，但等待用户选定；不为了凑选项增加无关系统。

## 受众、题材和美术

受众按“喜欢什么、追求什么、当前玩法怎样满足”描述。年龄、平台习惯、时长、难度等仅在有助于设计时补问。多类人群可并列，相关兼容问题留待验证。

题材说明世界、身份与活动如何承接玩法。先给大方向，让用户选、组合或脑暴；不强行完善尚未被要求的细节。

美术支持文字、截图、角色图、场景图和 UI 图。先看图，再说具体特征。绘画语言与具体物件分开，不从怪物截图推出必须采用相同世界观。

## 汇总与记录

最终确认整份方案，包含市场分析、参考改编、差异化、风险和待定项。用户接受后直接制作，不重复确认。

长对话可在当前工作区保留简短项目记录：已确认、待定、提案、参考范围、内部调研依据、已选图片。不要写入用户记忆目录。每个项目单独记录，避免带入上个案例的玩法或题材。
